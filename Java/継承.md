## **インターフェースとは？**
インターフェース（`interface`）とは、**「クラスが持つべきメソッドのルールを定めたもの」** です。

---

## **1. インターフェースの特徴**
| **特徴** | **説明** |
|---------|---------|
| **メソッドの定義だけを持つ** | 具体的な処理を持たず、メソッドの名前・引数・戻り値の型だけを定める。 |
| **クラスが `implements` で実装する** | インターフェースを実装したクラスは、すべてのメソッドをオーバーライド（実装）する必要がある。 |
| **多重実装が可能** | クラスは複数のインターフェースを同時に実装できる。（`implements A, B`） |
| **フィールドは `public static final`（定数）のみ** | インターフェース内のフィールドはすべて `public static final`（定数）として扱われる。 |

---

## **2. インターフェースの基本構造**
### **📌 インターフェースの定義**
```java
interface Animal {
    void makeSound(); // メソッドの定義（処理なし）
}
```

### **📌 インターフェースを実装するクラス**
```java
class Dog implements Animal {
    public void makeSound() { // インターフェースのメソッドをオーバーライド（実装）
        System.out.println("ワンワン");
    }
}

class Cat implements Animal {
    public void makeSound() {
        System.out.println("ニャーニャー");
    }
}
```

### **📌 `main` メソッドで使ってみる**
```java
public class Main {
    public static void main(String[] args) {
        Animal myDog = new Dog();
        myDog.makeSound(); // 出力: ワンワン

        Animal myCat = new Cat();
        myCat.makeSound(); // 出力: ニャーニャー
    }
}
```

### **💡 ここがポイント！**
✔ **インターフェースは「動作のルール」を定めるだけで、処理は書かない！**  
✔ **`implements` したクラスは、インターフェースのすべてのメソッドを実装しなければならない！**  
✔ **`Animal myDog = new Dog();` のように、インターフェース型の変数にオブジェクトを代入できる！**  

---

## **3. インターフェースの活用例**
### **(1) 共通の処理を定義する**
インターフェースを使うと、**異なるクラスに共通の動作を定義できる**。

```java
interface Vehicle {
    void move();
}

class Car implements Vehicle {
    public void move() {
        System.out.println("車が走る");
    }
}

class Bicycle implements Vehicle {
    public void move() {
        System.out.println("自転車が進む");
    }
}

public class Main {
    public static void main(String[] args) {
        Vehicle v1 = new Car();
        Vehicle v2 = new Bicycle();
        
        v1.move(); // 車が走る
        v2.move(); // 自転車が進む
    }
}
```
**💡 ポイント**
- `Vehicle` インターフェースを使うことで、**`Car` も `Bicycle` も `move()` メソッドを持つことが保証される**。
- `Vehicle` 型の変数 `v1, v2` を使えば、どの乗り物でも共通の方法で動かせる。

---

### **(2) 多重実装（複数のインターフェースを実装）**
Java では、**1つのクラスが複数のインターフェースを同時に実装できる**（多重実装）。

```java
interface Flyable {
    void fly();
}

interface Swimable {
    void swim();
}

class Bird implements Flyable {
    public void fly() {
        System.out.println("鳥が飛ぶ");
    }
}

class Duck implements Flyable, Swimable { // 🦆 アヒルは飛べるし泳げる
    public void fly() {
        System.out.println("アヒルが飛ぶ");
    }

    public void swim() {
        System.out.println("アヒルが泳ぐ");
    }
}

public class Main {
    public static void main(String[] args) {
        Duck d = new Duck();
        d.fly();  // アヒルが飛ぶ
        d.swim(); // アヒルが泳ぐ
    }
}
```

### **💡 ポイント**
✔ **`Duck` は `Flyable` と `Swimable` の両方を実装できる！**  
✔ **「飛べるもの」「泳げるもの」を分類でき、異なる特性を持つクラスに同じメソッドを持たせることができる！**  

---

## **4. インターフェースと `abstract` クラスの違い**
| **比較項目** | **インターフェース (`interface`)** | **抽象クラス (`abstract class`)** |
|-------------|---------------------------------|-------------------------------|
| **フィールド** | `public static final`（定数のみ） | 普通のフィールドを持てる |
| **メソッドの実装** | すべてのメソッドが抽象メソッド（`default` 以外） | 抽象メソッドと具体的なメソッドの両方を持てる |
| **コンストラクタ** | **なし** | **あり** |
| **継承の数** | **複数のインターフェースを実装可能** | **1つのクラスしか継承できない** |

**💡 使い分けのポイント**
- **「動作のルール」を定めるならインターフェース**
- **「共通の処理を持たせたい」なら抽象クラス**

---

## **5. まとめ**
| **ポイント** | **説明** |
|------------|----------------------------------|
| **インターフェースは「ルール」を定めるもの** | メソッドの名前・引数・戻り値の型だけを定義 |
| **`implements` を使って実装する** | クラスは `implements` でインターフェースを実装 |
| **多重実装ができる** | 1つのクラスが複数のインターフェースを実装可能 |
| **オブジェクトの共通化が可能** | インターフェース型の変数で異なるクラスのオブジェクトを扱える |
| **`abstract class` とは違う** | インターフェースは「メソッドの宣言のみ」、抽象クラスは「処理を含められる」 |

---

## **💡 インターフェースを使えば、異なるクラスに共通のルールを適用できる！**
✔ **「このメソッドを必ず持たせたい」ならインターフェース！**  
✔ **「動作の分類（例：飛べる・泳げる）」をしたいならインターフェース！**  
✔ **「共通の処理を持たせたい」なら抽象クラス！**  

これを理解すれば、**インターフェースを自由に使いこなせるようになるよ！** 🚀


### **インターフェースの実践的な活用例**

インターフェースを使うと、**異なるクラスに共通のルールを強制し、プログラムの拡張性を高めることができる** というメリットがあります。  
今回は、**実際の業務システムを想定したサンプルコード** で詳しく解説します。

---

## **1. インターフェースの基本構造（Webアプリのデータ保存）**
### **📌 シナリオ**
企業の Web アプリでは、データを **「データベース」または「ファイル」** に保存する機能があるとします。  
このとき、どちらの方法でも **「保存（`save()`）」と「読み込み（`load()`）」の機能は共通** です。  

✅ そこで、**インターフェースを使って「保存」と「読み込み」のルールを定義** します。

---

### **📌 インターフェースの定義**
```java
interface DataStore {
    void save(String data);
    String load();
}
```
✔ **「データを保存・読み込む機能がある」ことを保証するインターフェース**  
✔ **実装クラスは `save()` と `load()` を必ず持たなければならない**  

---

### **📌 データベースに保存するクラス**
```java
class DatabaseStore implements DataStore {
    @Override
    public void save(String data) {
        System.out.println("データベースに保存: " + data);
    }

    @Override
    public String load() {
        return "データベースからデータを取得";
    }
}
```
✔ **データベースにデータを保存・取得する処理を実装**  

---

### **📌 ファイルに保存するクラス**
```java
import java.nio.file.*;
import java.io.IOException;

class FileStore implements DataStore {
    private static final String FILE_PATH = "data.txt";

    @Override
    public void save(String data) {
        try {
            Files.writeString(Path.of(FILE_PATH), data);
            System.out.println("ファイルに保存: " + data);
        } catch (IOException e) {
            System.out.println("ファイル保存エラー: " + e.getMessage());
        }
    }

    @Override
    public String load() {
        try {
            return Files.readString(Path.of(FILE_PATH));
        } catch (IOException e) {
            return "ファイル読み込みエラー";
        }
    }
}
```
✔ **データをテキストファイルに保存・読み込む実装**  
✔ **`Files.writeString()` を使って簡潔に保存可能**  

---

### **📌 `main` メソッドで実際に使ってみる**
```java
public class Main {
    public static void main(String[] args) {
        DataStore dbStore = new DatabaseStore();
        dbStore.save("ユーザー情報: ID=123");
        System.out.println(dbStore.load());

        DataStore fileStore = new FileStore();
        fileStore.save("設定情報: Config=ON");
        System.out.println(fileStore.load());
    }
}
```
---

### **📌 実行結果**
```
データベースに保存: ユーザー情報: ID=123
データベースからデータを取得
ファイルに保存: 設定情報: Config=ON
設定情報: Config=ON
```

---

## **2. インターフェースを使うメリット**
| **メリット** | **説明** |
|------------|--------------------------------|
| **共通のインターフェースで管理できる** | `DataStore` インターフェースがあるため、`DatabaseStore` や `FileStore` を **同じように扱える** |
| **拡張性が高い** | **新しいデータ保存方法（例: クラウドストレージ）を追加しても、`save()` と `load()` を実装するだけ** で済む |
| **具体的な実装に依存しない** | **メインのプログラムは `DataStore` 型を使うので、どの実装を使っているかを意識せずに動作する** |

---

## **3. インターフェースの多重実装（複数の機能を持つクラス）**
### **📌 シナリオ**
クラウド上で動作するデータ管理システムでは、**データを保存する機能（`DataStore`）** に加えて、  
**ログを記録する機能（`Logger`）** も求められます。

✅ そこで、**`DataStore` に加えて `Logger` も実装するクラスを作ります。**

---

### **📌 ログ出力のためのインターフェース**
```java
interface Logger {
    void log(String message);
}
```
✔ **「ログ出力する機能を持つ」ことを保証**  
✔ **`log()` メソッドを必ず実装する**

---

### **📌 クラウドデータストレージの実装**
```java
class CloudStore implements DataStore, Logger {
    @Override
    public void save(String data) {
        System.out.println("クラウドにデータを保存: " + data);
        log("保存操作が実行されました");
    }

    @Override
    public String load() {
        return "クラウドからデータを取得";
    }

    @Override
    public void log(String message) {
        System.out.println("[LOG]: " + message);
    }
}
```
✔ **クラウドにデータを保存しつつ、ログも記録する**  
✔ **`DataStore` と `Logger` の両方の機能を持つ！**  

---

### **📌 `main` メソッドで実際に使ってみる**
```java
public class Main {
    public static void main(String[] args) {
        CloudStore cloudStore = new CloudStore();
        cloudStore.save("クラウド設定データ");
        System.out.println(cloudStore.load());
    }
}
```

---

### **📌 実行結果**
```
クラウドにデータを保存: クラウド設定データ
[LOG]: 保存操作が実行されました
クラウドからデータを取得
```

## **4. インターフェースと抽象クラスの使い分け**
| **比較項目** | **インターフェース (`interface`)** | **抽象クラス (`abstract class`)** |
|-------------|---------------------------------|-------------------------------|
| **目的** | クラスが **持つべき動作のルールを定める** | クラスの **共通処理を実装する** |
| **メソッドの実装** | なし（`default` を除く） | 抽象メソッドと具体的なメソッドの両方を持てる |
| **フィールド** | `public static final` の定数のみ | 普通のフィールドを持てる |
| **コンストラクタ** | なし | あり |
| **多重実装の可否** | **可能（複数のインターフェースを `implements` できる）** | **不可能（`extends` は 1 つのみ）** |

---

## **5. まとめ**
| **ポイント** | **説明** |
|------------|----------------------------------|
| **インターフェースは「ルール」を定めるもの** | メソッドの名前・引数・戻り値の型だけを定義 |
| **`implements` を使って実装する** | クラスは `implements` でインターフェースを実装 |
| **多重実装ができる** | 1つのクラスが複数のインターフェースを実装可能 |
| **インターフェースを使うと拡張しやすい** | 新しい機能を追加するときに、影響を最小限に抑えられる |
| **抽象クラスとは異なる** | インターフェースは「動作のルール」、抽象クラスは「共通処理を持つ」 |
